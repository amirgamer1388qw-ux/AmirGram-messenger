AmirGram — SETUP & HOSTING GUIDE
================================
GitHub: https://github.com/amirgamer1388qw-ux

This file is a complete guide for setting up and running AmirGram from start to finish.

1) Requirements
---------------
Windows / Linux / Android:
- Node.js must be installed.
- Access to Terminal/CMD.
- SSH access for VPS hosting.

2) Running Locally on Windows
-----------------------------
1. Extract the project folder.
2. Open CMD inside the AmirGram project folder.
3. Run:

   npm install

4. Then start the server:

   npm start

5. Open your browser:

   http://localhost:3000

To stop the server in the same Terminal:
Ctrl + C

3) Changing the Invite Code
---------------------------
The easiest method is to start the application and create the first account.
The first registered account becomes the group administrator.

Default invite code on the first run:

   team2026

To configure the invite code before starting the application on Windows CMD:

   set TEAM_INVITE_CODE=YOUR_SECRET_CODE
   npm start

After settings.json has been created, the invite code can also be changed from the admin panel.

4) Where Is the Data Stored?
----------------------------
data/
- users.json
- messages.json
- seen.json
- settings.json

Before moving the server to another machine or host, make sure to back up the data/ directory.

5) Running on Android / Termux
------------------------------
Run:

   pkg update
   pkg install nodejs openssh
   termux-setup-storage

Then enter the project directory and run:

   npm install
   npm start

If the project files are stored in shared storage, use quotation marks around the folder path if it contains spaces.

Example:

   cd ~/storage/shared/"fg pas"/team-messenger-v9

6) Temporarily Making the Server Public for Testing
----------------------------------------------------
If you are running AmirGram on your personal computer and only need a temporary public link for testing, you can use a tunnel.

Example using localhost.run:

Terminal 1:

   npm start

Terminal 2:

   ssh -R 80:127.0.0.1:3000 nokey@localhost.run

Use the link printed by the tunnel for testing.

Both Terminals must remain open.

Note: Tunnel links are usually temporary and are not recommended for the main production service.

7) Hosting on a VPS
-------------------
General recommendations:

- Ubuntu LTS
- At least 2 CPU cores
- Around 2–4 GB RAM to start
- SSD/NVMe storage
- Public IPv4 address

On the VPS:

1. Install Node.js.
2. Transfer the project to the server or clone it from Git.
3. Inside the project directory:

   npm install

4. Test the application:

   npm start

5. After confirming that everything works, use a process manager such as PM2 for permanent execution.

Example:

   npm install -g pm2
   pm2 start server.js --name amirgram
   pm2 save
   pm2 startup

8) Domain
---------
If you have a domain such as:

   amirgram.example

Configure its DNS to point to the server's IP address.

For a VPS, a typical setup uses an A record that points the main domain to the server's public IPv4 address.

9) HTTPS
--------
For a public service, enable HTTPS.

A common method is to use Nginx as a Reverse Proxy and obtain a TLS certificate from Let's Encrypt.

Typical architecture:

   Internet -> HTTPS/Nginx -> http://127.0.0.1:3000 -> AmirGram

If you use Cloudflare, configure DNS/Proxy and TLS according to your current Cloudflare settings.

10) Reverse Proxy with Nginx
----------------------------
Install Nginx on the VPS and configure it to forward domain requests to port 3000.

After HTTPS is enabled, users should access AmirGram using:

   https://

11) WebSocket / Socket.IO
-------------------------
AmirGram uses Socket.IO.

The Reverse Proxy must support WebSocket connections.

Configure Nginx so that the Upgrade and Connection headers are correctly forwarded for WebSocket communication.

12) Security Before Public Release
----------------------------------
- Use strong, real passwords.
- Change the default invite code.
- Do not expose port 3000 directly to the Internet if you are using Nginx/Reverse Proxy.
- Regularly back up the data/ directory.
- Keep Node.js and all dependencies up to date.
- Run the public service only behind HTTPS.
- For a real production service, add rate limiting, proper session management, and additional security testing.

13) Backups
-----------
Before making important changes:

- Back up the entire project.
- Especially keep a backup of the data/ directory.

14) Updating the Project
------------------------
1. Back up the previous version.
2. Replace the old files with the new version.
3. If package.json has changed:

   npm install

4. Restart the service.

15) Common Troubleshooting
--------------------------
If npm install fails:

- Check the Node.js version:

   node -v

- Check the npm version:

   npm -v

- Check your Internet connection and access to npm.

If port 3000 is already in use:

- Find and stop the application using the port, or change the PORT value in server.js.

If users cannot connect from the Internet:

- Check the public IP/DNS, Firewall, Reverse Proxy, and Tunnel.
- Installing HTTPS alone does not solve connectivity problems; the server must be reachable from the Internet.
